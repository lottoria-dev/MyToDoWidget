# 1.1.2 Windows 확인 순서

Visual Studio에서 .NET 10 / .NET 데스크톱 개발 워크로드로 빌드하세요.
기본값은 정식판입니다. 기존 앱을 트레이에서 완전히 종료한 뒤 확인하세요.
정식판 설정과 분리해 시험할 때는 `-p:MyToDoTestBuild=true`를 명시합니다.

1. 메모 전용 시트를 만들고 A열을 일반 텍스트로 지정합니다.
2. A1부터 한글·숫자·자유 날짜·따옴표·쉼표·여러 줄을 입력합니다. A1도 메모이며 제목 행은 없습니다.
3. 공유 → 일반 액세스에서 ‘링크가 있는 모든 사용자 · 뷰어’를 선택합니다.
4. 메모 탭을 연 브라우저 주소를 설정 → 연결·동작에 등록합니다.
5. A열 순서·빈 셀 제외·줄바꿈을 확인하고, 다른 탭 주소로 교체해서 올바른 탭을 읽는지 확인합니다.
6. 시트 수정 후 F5를 눌러 최신 내용이 표시되는지 확인합니다. A열 전체를 비운 정상 응답에서는 목록도 비어야 합니다.
7. 기존 다크 설정에서 실행해도 환경설정창이 밝게 표시되고, 모양·꼬리·정렬·가로 폭·글꼴 드롭다운의 선택값과 펼친 항목이 읽히는지 확인합니다. 유리판의 ‘밝은 테마’ 옵션은 없어야 합니다.
   말풍선·유리판 색상 미리보기 중에도 설정창은 밝게 유지되어야 합니다.
8. 설정을 다시 열면 주소를 보여 주지 않고 등록 여부만 표시하는지 확인합니다.
9. 시트 접근을 ‘제한됨’으로 바꾼 뒤 F5를 누릅니다. 오류를 알리고 기존 메모·갱신 시각을 유지해야 합니다.
10. 다른 주소 등록에 실패하거나 저장을 취소하면 기존 연결이 유지되는지 확인합니다.
11. 연결 해제 후 재실행 시 메모가 돌아오지 않는지 확인합니다. Google 원본·공유 권한은 그대로여야 합니다.
12. 우클릭 / 말풍선 더블클릭은 구글 시트 목록을 여는지 확인합니다.
13. 한 줄·여러 줄 메모에서 줄인 상하 내부 여백과 글자 잘림 여부를 확인합니다. 5가지 모양·3가지 꼬리·크기 조절에서 확인하고, 기존 글꼴·불투명도·롤업·스크롤·잠금/절전 복귀도 점검합니다.
14. Windows 자동 실행을 켜고 저장한 뒤 로그인 동작을 확인합니다. 시험이 끝나면 자동 실행을 끄고 저장하세요.

테스트 데이터에는 개인정보를 넣지 마세요. 실제 학교·학생 정보를 시험에 사용할 필요가 없습니다.

핵심 로직 자동 확인: `run_checks.bat` 또는 README의 `dotnet run` 명령을 사용합니다.
이 검사는 모의 HTTP 응답과 임시 저장 폴더를 쓰며 Google 공유 설정이나 Windows 레지스트리를 수정하지 않습니다.
